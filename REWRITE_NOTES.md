# Notes for the rewrite: what went wrong and what to watch for

Read this before rewriting the reconstruction code. It records one bug found in
the prototype (Nov 2026), how it was fixed, how the fix was checked, and the
traps found along the way. Numbers come from a NEMA NU 4 IQ run simulated with
MCGPU-PET (`mpw.default_config()`, span 1, 75 rings, 2 mm ring pitch, 1 mm voxels,
`nema_iq_preclinical(cfg, hot_activity_Bq_per_mL=20000)`).

## 1. The bug: no per-LOR sensitivity in the system model

**Symptom.** NEMA IQ recovery coefficients (RC) above 1 for every method:
1.2-1.3 for the rods, even at full dose and 100 MLEM iterations. In this
phantom the rods and the uniform region have the same activity, so the true
RC is exactly 1.

**Cause.** `MCGPUProjector` (`mcgpu_recon/projector.py`) modeled each sinogram
bin as the Joseph line integral of the image along the LOR, with no geometric
sensitivity per LOR. Two things go wrong for an LOR at angle theta to the
transverse plane:

- Its real detection probability falls about as cos^3(theta): the inverse
  square of a longer distance, times slanted incidence on the crystal face.
- The Joseph integral grows as 1/cos(theta), the longer path through each voxel.

So oblique LORs were weighted about 1/cos^4(theta) too heavily. The model's
axial sensitivity was too peaked at the scanner centre: it predicted about 5%
too many counts at the centre and about 14% too few 25 mm off-centre. The rods
are at one axial end of the phantom and the uniform region (the RC
denominator) is near the centre. MLEM made the rods 10-15% too bright to
match the data.

**Evidence** (MCGPU sinogram counts / model counts per ring difference,
normalised to the same total):

| Ring difference | 0 | 24 | 48 | 72 |
| --- | --- | --- | --- | --- |
| No weight | 1.856 | 1.262 | 0.538 | 0.216 |
| cos^4 weight | 1.001 | 1.002 | 0.999 | 0.998 |

A cos^k fit to the unweighted ratio gave k = 4.03-4.08 across all ring differences.

## 2. The fix in the prototype (committed 2026-11-16)

- `projector.py`: forward and adjoint multiply each bin by
  `w = cos^4(theta) = (D^2 / (D^2 + dz^2))^2`. Here `D` is the transverse
  chord length of the bin and `dz` is the axial offset between its two rings;
  both mirror lines of a plane share it. `oblique_weight=False` restores the
  old model. The weight is applied in BOTH `__call__` and `adjoint`, so the
  adjoint test still passes (~3e-7).
- New `MCGPUProjector.line_integral(x)`: the unweighted forward projection.
- `attenuation.py`: `attenuation_factors` uses `A.line_integral` if present.

**Trap hit while fixing it:** `attenuation_factors` computed `exp(-A(mu))`.
Once `A` includes a sensitivity weight, `A(mu)` is no longer a path length, so
attenuation was under-corrected for oblique LORs and the fix only half worked
(ratio 1.13 down to 0.68 instead of flat). **In the rewrite, keep the geometric
line integral and the sensitivity/normalization as separate pieces**, e.g.
`A = diag(norm * att) @ G`, where `G` is the pure line-integral projector and
attenuation is computed with `G` alone.

**Result** (mean RC inside the rod core, MLEM 100 it):

| Data | Before (3 / 4 / 5 mm) | After |
| --- | --- | --- |
| Full dose | 1.13 / 1.13 / 1.12 | 1.01 / 1.00 / 1.00 |
| 10% dose | 1.15 / 1.13 / 1.14 | 1.03 / 1.00 / 1.02 |

The fix also lowered spill-over into the cold inserts and the uniform-region
%STD at a given smoothing setting (e.g. MLEM + 2 mm filter: 7.3% to 5.3%), so
contrast-vs-noise curves from before the fix are not comparable with those after.

## 3. Limits of the fix

- cos^4 was **checked only against MCGPU-PET**, which simulates an ideal
  scanner. It is a physics-motivated weight, confirmed empirically; it is not a
  general normalization.
- **Real data (Bruker PET insert) needs a measured normalization**: crystal
  efficiencies, detector gaps, dead time and block effects vary per LOR, and
  cos^4 covers none of them. Without it, the same kind of axial bias can return.
  Typical source: a uniform cylinder or rotating-rod scan, or the vendor's
  normalization file.
- A small transverse residual remains: about 2% low near the edge of the
  radial FOV (radial bin centre+30) for direct planes. It was not investigated.
- In MCGPU itself, detector efficiency is uniform. If a future MCGPU config
  adds depth of interaction or crystal gaps, re-check the weight with the tests
  below.

## 4. Other traps found

- **NEMA RC uses the max voxel, so it is biased upward by noise.** RC > 1 at
  high noise is expected even with a correct model (e.g. 1.23-1.35 at 10% dose,
  100 MLEM iterations, after the fix). To check quantitative accuracy, also
  report the mean inside the rod core (radius d/2 - 0.5 mm, central 10 mm).
- **Early MLEM iterations can overshoot small hot rods.** On noise-free data
  generated by the model itself, 23 iterations gave a mean RC of 1.08 for the
  3 mm rod; 100 iterations gave 1.00. Don't treat early-stopped MLEM RC as
  ground truth.
- **PMMA and water share MCGPU material id 2** in `nema_iq_preclinical` (PMMA =
  density 1.19). The `MU_RHO` dict is keyed by material id, so PMMA gets water's
  mass attenuation coefficient (0.096 vs about 0.093 cm^2/g), about 1% error over
  the phantom. The MR surrogate in `examples/demo_map_em.py` also tells PMMA
  from water by density, not by id.
- **MCGPU's `image_Trues.raw.gz`** (`mpw.read_emission_image`) counts DETECTED
  trues per voxel of origin. Its total equals the trues sinogram total, so it
  gives the scanner's real per-voxel sensitivity (including attenuation) and is
  the best reference for the model's sensitivity image `A^T(att)`.

## 5. Tests to keep in the rewrite

Run these whenever the system model changes. The first two need no GPU-heavy
reconstruction.

1. **RC of the true image = 1.00** (checks the metric and the ROI geometry).
2. **Sinogram ratio by ring difference is flat:** compare the MCGPU trues
   sinogram with `att * A(truth_activity)` grouped by `|ring1 - ring2|`; after
   global scaling, every group should be 1.00 +- 0.01.
3. **Sensitivity matches MCGPU per slice:** for each z slice, take
   `sum(image_Trues) / sum(activity * A^T(att))` over hot voxels; it should be
   flat along z.
4. **Model self-consistency:** MLEM on noise-free data `att * A(truth)` reaches
   RC 1.00 at about 100 iterations.
5. **Adjoint test:** `adjoint_test(A)` below about 1e-5.

Minimal code for test 2:

```python
y, r1, r2 = mpw.read_sinogram_ring_pairs(run_dir, cfg)   # trues, span 1
af = attenuation_factors(A, xp.asarray(attenuation_map_from_vox(vg, MU_RHO)))
ym = (af * A(xp.asarray(np.asarray(vg.activity, np.float32)))).get()
k = y.sum() / ym.sum()
rd = np.abs(np.asarray(r1) - np.asarray(r2))
ratio = [y[rd == d].sum() / ym[rd == d].sum() / k for d in range(rd.max() + 1)]
```
